Secure messaging · Opp-BiKEM · M8, stage A of four

Stop, Inject, Cancel

Everything that remains of the Opp-BiKEM security proof is one inequality per epoch: two adjacent hybrids differ by at most the IND-CPA advantage of an explicit reduction. This page explains the first stage of that argument, which is now proved: the hybrids may be stopped the moment the target epoch is exposed, without changing their difference. It also fixes the reduction, once and for all, and lays out the three stages that will connect the stopped hybrids to it.

Snapshot: 25 October 2026, the unstaged stage A changes above commit 848b09e (M7). Stages B, C and D are planned, not proved. Their statements below are intentions, frozen only when they land.

01

The skeleton is complete; the core is one hypothesis

M7 built the epoch hybrids. The hybrid with threshold T answers every accepted challenge of an epoch below T with a fresh random key and every other accepted challenge with the recorded table key. The hybrid with threshold 0 is the ideal game with bit false; the hybrid with threshold 2q + 1 has the same output distribution as the ideal game with bit true, because no epoch above 2q is ever keyed. The telescoped theorem sckaGuessAdvantage_le_of_hop_bound then bounds the adversary's advantage by q · εcor plus half the sum of the adjacent-hybrid gaps, provided each positive-epoch gap is at most some δt.

02

The hop that remains

Write HT for the hybrid with threshold T. Fix a target epoch t ≥ 1. The hybrids Ht+1 and Ht select the same answer at every epoch other than t: Ht+1 answers the challenge of t with a random key, Ht with the table key. The obligation is:

| Pr[Ht+1 = true] − Pr[Ht = true] | ≤ AdvIND-CPAKEM(reductiont) For every 1 ≤ t ≤ 2q. The hop at t = 0 is exact (epoch 0 is never keyed), so no reduction is needed there.

Two conventions, fixed in the roadmap and confirmed by the M7 evaluation, decide which hybrid pairs with which KEM branch. In the SCKA game, a selection value of true means "answer with a random key". In VCVio's IND-CPA experiment, bit true means "the real encapsulated key". So Ht, which hands out the table key at t, corresponds to the KEM experiment with bit true, and Ht+1 to bit false. The absolute value in the final bound hides this, but the branch-by-branch statements in stage D must name it.

The two hybrids differ at exactly one place: the answer to an accepted challenge of epoch t. Everything in stages A to D is about isolating that one place and handing it to a KEM challenger.

03

Why this is four stages and not one

The request was to prove everything to the end in one go. The honest answer is that the remainder is the cryptographic core of the project, and it is large. The repository's existing CKA-from-KEM reduction, for a non-adaptive scheme with a perfectly correct KEM, is about 9,200 lines over 14 files. Opp-BiKEM adds adaptive target epochs, two interleaved roles, erasure-coded chunks, leaking sends, corruptions and an imperfect KEM. The remaining work is estimated at 2,500 to 3,500 lines and uses three genuinely different proof technologies.

The four stages, each with its own build, lint, axiom audit and review

The order is chosen so that each later stage consumes exactly one new technology and the reduction never changes after stage A. A reviewer of stage B can read the reduction's definition and know it is the object the final theorem will speak about.

04 · the idea

Why the hybrids may be stopped at exposure

A reduction that embeds a KEM challenge at epoch t cannot answer a query that would reveal the secret key or the encapsulation coins of t. It does not have them. If the adversary exposes t, by a leaking send that generates or encapsulates for t, or by corrupting the owner while the secret of t is retained, the simulation must give up.

The SCKA game's guards make giving up harmless. Consider what the two hybrids do relative to the order of two events, the challenge of t and the exposure of t.

Exposure first

Once t is exposed, the challenge oracle rejects every later challenge of t. The one query on which the hybrids differ can no longer be accepted. From any state with t exposed, Ht+1 and Ht produce the same output distribution on every remaining computation.

Challenge first

Once the challenge of t is accepted, t is in the challenged set, and the exposure policy rejects any later leaking send or corruption that would expose a challenged epoch. The epoch t is now committed: challenged and never exposed, in both hybrids, for the rest of the run.

So the runs where the simulator would have to give up are exactly runs on which the two hybrids agree. Replacing both hybrids' output by false at the first query after which t is exposed subtracts the same quantity from both acceptance probabilities. The difference is unchanged.

targetExposed t s   := decide (t ∈ s.exposed)          -- the stopping test
TargetCommitted t s := t ∈ s.challenged ∧ t ∉ s.exposed  -- the committed states

stoppedHybridExp t T adv :=
  stoppedRun (hybridSecurityImpl … (hybridRandom T)) (targetExposed t) adv initState

stoppedRun is ToVCVio's generic construction: run the oracles as usual, but after each query check the state; if the test holds, abort the whole computation with output false.

05 · proved

The cancellation theorem

Pr[Ht+1 = true] − Pr[Ht = true] = Pr[St+1 = true] − Pr[St = true] ST is stoppedHybridExp t T: the hybrid with threshold T, stopped at exposure of t. Theorem hybridExp_sub_eq_stopped_sub, for every adversary and every t.

The theorem is an instance of ToVCVio's signed_gap_stoppedRun_eq, a generic statement about two oracle implementations, an invariant, a set of committed states and a stopping test. Four facts are supplied; all four are about single queries from single states, never about whole runs.

The per-query agreement lemma uses the M7 fact that two selections give the same challenge computation whenever they agree on all epochs eligible in the current state, plus a one-line lemma that thresholds t + 1 and t select the same answer at every epoch other than t.

What stage A does not need: the game invariant, correctness of the erasure codes, the query bound, or any property of the KEM. The cancellation holds for every adversary, every target and every scheme instance. That is why it could be proved before the invariant for injected runs exists.

Every sequence ends in one of three regimes. Committed: the hybrids differ at the one accepted challenge, and no stop can ever happen. Stopped: both hybrids output false from here on, and they would have agreed anyway. Still eligible: nothing has happened yet.

07 · defined and frozen

The reduction

The reduction for target t is an IND-CPA adversary against the KEM. It receives a public key pk*, then a ciphertext c* and a candidate key k* that is either the key encapsulated in c* or an independent uniform key. It must say which. It does so by running the SCKA adversary in a simulated game where the KEM values of epoch t are the challenge values.

reduction adv t : kem.IND_CPA_Adversary where
  State         := PK
  preChallenge  := pure                       -- nothing happens before the challenge
  postChallenge := fun pk c k => reductionRun adv t pk c k

reductionRun adv t pk* c* k* := do
  let (_, dummySk) ← kem.keygen             -- placeholder for the secret it does not have
  stoppedRun (injectedSecurityImpl t ⟨pk*, dummySk, c*, k*⟩ (hybridRandom t))
             (targetExposed t) adv initState

The simulated oracles are the ordinary ten: uniform sampling, two ordinary sends, two ideal receives, the challenge, two leaking sends and two corruptions. Only the ordinary sends are modified, and only at two sites.

What the reduction never reads

It never reads the secret key of pk*, which it does not have. It never decapsulates, because receives are ideal. The placeholder secret sits in the owner's list of retained secrets and is only ever looked up by the ideal receive, which ignores its value. The randomness of the KEM challenge is never touched. When a leaking send would leak the coins of t's key generation or encapsulation, or a corruption would reveal the retained secret of t, the exposed set gains t and the run stops.

Every definition in the reduction file is computable. The data flow is small enough to audit by eye, which is the reason to freeze it now: stages B to D prove facts about this object and never redefine it.

Why a placeholder secret at all? The honest state stores a secret for every retained key epoch, and the receive algorithm looks one up before recovering the key. Storing a freshly generated, unrelated secret keeps the state's shape identical to the honest one, so the stage D state map is a value replacement, not a structural change. Drawing it from an independent key generation is sound because that sample is never used and integrates out.

08 · proved, generic

Three bookkeeping lemmas for any SCKA scheme

The cancellation theorem needs to know how one security query moves the exposed and challenged sets. This was proved once, in the generic SCKA security file, for any scheme and any exposure policy, as three insertion-only additions.

LemmaStatement
oracleSendArleak_bookkeeping, oracleSendBrleak_bookkeepingA leaking send keeps the challenged set and grows the exposed set by a set disjoint from the challenged set; on rejection, by the empty set.
securityImplOf_bookkeepingGiven that base queries keep both sets and challenges keep exposed without shrinking challenged, every assembled security query shrinks neither set, and every newly exposed epoch was not challenged before.

The Opp-BiKEM instance discharges the base-query premise by checking the five ideal correctness oracles, and the challenge premise by the existing support characterisation of the challenge oracle. The result hybridSecurityImpl_bookkeeping then yields both preservation facts the gap theorem asks for, in two lines each. The same generic lemma will serve the injected oracles in stage B without change, since they are assembled by the same securityImplOf.

09 · planned

Stage B: what injected runs look like

Stages C and D will compare the injected oracles with the honest ones query by query. For that they need facts about every state reachable under the injected oracles with any selection: the target's public key, secret, ciphertext and recorded key are the injected ones wherever they appear. The planned invariant InjInv bundles the existing game invariant with four pinning clauses.

ClauseMeaningWhere it is used
gameInvThe ordinary GameInv, with its transcript witness.Everywhere; it supplies the control-flow facts about sends and receives.
key_pinnedFor every transcript witness, the key pair recorded at t has public key inj.pk.The encapsulation site: the peer's stored key for t is pk*, so honest encapsulation there is to pk*.
secret_pinnedAny secret retained for epoch t is inj.sk.Stage D's state map replaces exactly that value by the placeholder.
table_pinnedEach table's entry at t is absent or inj.key.The challenge of t returns the injected key in both the eager hybrid and the reduction.
ct_pinnedFor every witness, the encapsulation recorded at t is (inj.ct, inj.key).Ideal receives copy the pinned value.

The clause key_pinned is the main risk. It is stated for all transcript witnesses rather than for one tracked transcript, so that preservation needs no bookkeeping of how the transcript changes across a step. The intended argument is state-based: while the owner still holds its public key at key epoch t, the invariant's clause ek_T pins it; once the owner has cleared it, the peer must have acknowledged decoding it, and ekPeer_T pins it from the peer's side. If some receive path resists this, the fallback is a transcript-tracking variant of the send step with one extra conclusion, as a new lemma with no statement change.

A correction from the stage A review. The invariant cannot be preserved by every query: a leaking send by the owner that generates the key pair of t samples a fresh honest pair, which need not be the injected one, and stores its secret at t. But that same send exposes t, and the run stops before the adversary sees anything further. So the preservation theorem is stated for continuing successors only, those with t still unexposed, which is exactly the shape the one-use sampling lemma and the stage D state map ask for. The lemma that a leaking send touching t always exposes t is what makes this restriction sufficient.

Stage B also plans first-use predicates: targetGenerated and targetEncapsulated are monotone state properties that become true exactly at the injected sites, and a leaking send that generates or encapsulates for t leaves t exposed in every successor, hence stops. These are what stage C's one-use lemma will consume as its "used" predicates.

10 · planned

Stage C: eager equals lazy on stopped runs

Stage C has since been executed as planned here, with the deviations listed in the stage C tutorial. This section keeps the plan as it stood after stage A.

The honest hybrid draws the key pair of epoch t at the owner's send, the encapsulation at the peer's send, and the random challenge answer at the challenge. The reduction receives all of these at the start. Stage C shows that drawing them eagerly does not change the stopped hybrid's output probability.

Pr[St+b = true] = E(pk,sk) ← keygen, (c,kreal) ← encaps pk, krand ← $K Pr[Eb(pk, sk, c, kreal, krand) = true] Eb is the eager hybrid: the injected oracles with the honest secret and the real key in the table, whose challenge of t answers krand if b = 1 and the table key otherwise, stopped at exposure of t.

The tool is the existing one-use sampling lemma in ToVCVio. It says: if a sample is consumed by at most one query, the query that consumes it is recognisable from the state, and no other query's behaviour depends on the sample, then drawing the sample up front and drawing it at the consuming query give the same output probability. It is applied three times, peeling one sample at a time.

To state the eager challenge answer, the generic challenge oracle is generalised to oracleChallWith, which takes an arbitrary answer function from epoch and table key to a distribution over keys. The existing selection-based oracle is an instance, by a one-line lemma, so nothing already proved moves.

11 · planned

Stage D: the state map and the public theorem

After stage C, the eager hybrid Eb and the reduction's run R(pk, dummy, c, kb) are the same oracle family up to the values stored at epoch t: the eager hybrid holds the honest secret and the real key in its tables and answers the challenge of t from kb; the reduction holds the placeholder secret and kb in its tables and answers the challenge from the table. A state map targetStateMap t dummy kb renames the first into the second.

Pr[Eb(pk, sk, c, kreal, krand) = true] = Pr[R(pk, dummy, c, kb) = true] with k0 = kreal and k1 = krand, for every placeholder dummy.

The proof is a per-query step of the state map over all ten oracles, under InjInv plus "t not exposed". Sends and receives commute with a value replacement in the retained-secret list and in the tables. The challenge agrees below t and above t trivially, and at t both sides return kb. Corruptions and leaking sends are honest on both sides: either rejected on both, equal on both, or stopped on both. The one new generic ingredient is a relaxed state-map transport lemma that asks only for equal mass of stop answers, since the two sides' stopped states need not be related by the map.

Assembly

Unfolding VCVio's IND-CPA experiment, the bit-true branch is the expectation over the KEM samples of R(pk, dummy, c, kreal), and the bit-false branch of R(pk, dummy, c, krand), with the placeholder draw integrating out. Chaining stages A, C and D with the fixed-branch form of the advantage gives the hop bound as an equality, and the M7 telescope turns it into the public theorem.

AdvSCKA(A) ≤ q · εcor + ½ Σt = 02q AdvIND-CPAKEM(reductiont) Planned as security in a new public module. The corollary security_uniform, q · εcor + q · δ when every positive-epoch reduction has advantage at most δ, is derived directly from the M7 telescope with a bound function that is zero at epoch 0, since the summand at 0 cannot be removed from security itself.

Note that the chain is a sequence of equalities, not inequalities. The only inequality in the final bound is the one M7 already proved, from the sum of hops to the guessing advantage. Nothing is lost in stages A to D.

Check your understanding

Separate the claims

Does stopping at exposure throw away adversaries that expose the target?

No. It throws away the same probability mass from both hybrids, because after exposure of t the two hybrids agree on everything. The difference, which is all the bound needs, is unchanged. The stopped runs are not a weaker game; they are the same gap written in a form a reduction can simulate.

Why can an exposure not follow an accepted challenge of t?

The exposure policy rejects any leaking send or corruption whose exposed epochs intersect the challenged set. Once the challenge of t is accepted, t is challenged, so every later attempt to expose it is rejected. The generic bookkeeping lemma records this as "every newly exposed epoch was not challenged before the query".

Why does stage A need no game invariant?

All its inputs are single-query facts about the exposed and challenged sets and about the selection values at eligible epochs. None of them depends on what the party states look like. The invariant enters in stage B, where the KEM values at the injected sites must be pinned.

Where does the reduction's placeholder secret end up, and is it ever used?

It is stored in the owner's retained-secret list at epoch t, exactly where the honest secret would be. The only consumer of that list is the receive algorithm, and in the ideal game the receive looks the secret up and then ignores it. Corruption would reveal it, but corruption while it is retained exposes t and stops the run first.

Which hybrid corresponds to the KEM's real-key branch?

Ht. It answers the challenge of t with the table key, which in the reduction is the KEM candidate k*. When k* is the encapsulated key, that is Ht; when k* is uniform, that is Ht+1, whose answer at t is a fresh random key. The sign flips relative to the hybrid index, and the absolute value absorbs it.

Why is the reduction defined before stages B to D are proved?

So that the object the final theorem speaks about is fixed and auditable now. If a later stage needed a different reduction, that would be a design change worth reviewing on its own; the plan's stop conditions allow new lemmas but not changes to the frozen definitions.

Why three separate one-use peels in stage C rather than one?

The three samples are consumed at three different queries, recognised by three different state predicates, and the encapsulation sample depends on the public key drawn by the first. Peeling one at a time keeps each application of the generic lemma a statement about one sample with one "used" predicate.
