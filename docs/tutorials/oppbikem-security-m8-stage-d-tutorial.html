Renamed at the Target

After stage C the eager hybrid and the reduction's simulation run the same oracles, except for what the game state holds at the target epoch: the eager hybrid keeps the honest secret and the real key, the reduction a placeholder secret and the candidate key. Stage D renames one into the other with a state map, shows that every oracle commutes with the map, and assembles the exact hop bound and the two public security theorems. The proof of Opp-BiKEM's security is complete.

One renaming away from the reduction

Stage A stopped the hybrids at the exposure of the target and defined the reduction. Stage B described the states of injected runs. Stage C showed that the stopped hybrid of threshold t + b is the eager hybrid Eb, averaged over the target's key pair, encapsulation and random key. What remains is to recognise Eb as the reduction's run on the KEM challenge.

Resultsecurity and security_uniform, with the statements planned at the start.

Both are stopped runs of injected oracles. The eager hybrid injects ⟨pk, sk, c, kreal⟩ and answers the challenge of t through the eager answer, which returns krand when b is set and the table entry otherwise. The reduction injects ⟨pk, dummy, c, kb⟩ and answers from the table. So the reduction's state holds dummy where the eager state holds sk, and kb where the eager state holds kreal. Everything else is the same.

02 · proved

The claim

Pr[Eb(pk, sk, c, kreal, krand) = true] = Pr[R(pk, dummy, c, kb) = true] probOutput_stoppedEagerExp_eq_reductionRun, for every placeholder dummy, with k0 = kreal and k1 = krand, under correct erasure codes, a positive target, and injected values that key generation and encapsulation can produce. R is the stopped run of the injected oracles with the selection of threshold t.

Note the universal placeholder. The reduction draws its placeholder from an independent key generation, and the equation says the acceptance probability does not depend on which one it drew. This is what lets the placeholder draw integrate out when the IND-CPA experiment is unfolded.

From the claim and the earlier stages, the hop at a positive target is exact, and the two theorems follow.

|Pr[Ht+1] − Pr[Ht]| = AdvIND-CPAKEM(reductiont) hybrid_hop_eq_reduction. The real-key branch of the KEM experiment is hybrid t, the random-key branch hybrid t + 1.
AdvSCKA(A) ≤ q · εcor + ½ Σt = 02q AdvIND-CPAKEM(reductiont) security. The sharper security_positive sums over the positive targets 1 ≤ t ≤ 2q only, and security_uniform gives q · εcor + q · δ when every reduction at a positive target up to 2q has advantage at most δ. Both are corollaries of the sharper form.
03 · implemented

The state map

The map targetStateMap t dummy k acts on a game state field by field. In each party's list of retained secrets, every entry at integer epoch t gets the secret dummy; the entries are kept, only their values change. In each key table, the entry at t becomes k if present and stays absent otherwise. Messages, counters, current epochs, the exposed and challenged sets and the correctness flag are untouched.

mapSecret t d st   -- st.req.dk.map (fun p => if p.1 = t then (p.1, d) else p)
mapTable  t k tbl  -- fun e => if e = t then (tbl e).map (fun _ => k) else tbl e
targetStateMap t d k s := { s with stA := mapSecret t d s.stA, stB := mapSecret t d s.stB,
                                   keyA := mapTable t k s.keyA, keyB := mapTable t k s.keyB }

Two design choices matter. The map replaces whatever sits at the target, not specifically the honest values. This makes the map's algebra unconditional: it commutes with prepending a new secret, with filtering by epoch, with table updates, and with the first-entry lookup the receive performs, with no invariant in sight. And it acts on both parties alike, so no lemma needs to know who owns the target.

Where the map must know the honest values is exactly one place: the challenge of t with b clear, where the eager side returns the table entry and the reduction returns the mapped entry kreal. There, stage B's table pinning says the entry is kreal.

Everything the oracles compute from a state and that the map could disturb reads only epochs, never secret values: the vulnerable set, the leaked epochs of a send, and the send guards. These facts are one-line simp lemmas, and the initial state is a fixed point of the map.

04 · generic

A relaxed transport lemma

ToVCVio already had a state-map transport lemma: if the right oracles from f s answer every query with the distribution of the left oracles from s, with the successor mapped through f, then both runs accept with the same probability. Stage A planned to use it. It cannot be used as is.

Consider a leaking send that generates the target's key pair. On both sides it is the honest send, so it draws a fresh honest secret and stores it at t. On the eager side the map then turns that fresh secret into dummy; on the reduction side the state holds the fresh secret itself. The two successors are not related by the map. The query exposes the target, so the stopped run discards the state, but the old lemma still asks the joint distribution of answer and mapped successor to agree, stopped answers included.

𝒟[(a, s') ↦ a.map (a ↦ (a, s')) ⟨right from f s⟩] = 𝒟[(a, s') ↦ a.map (a ↦ (a, f s')) ⟨left from s⟩] probOutput_optionRun_eq_of_state_map_some: the per-query obligation compares the answer paired with the successor on some answers; a none answer contributes only its mass and its state is dropped. Preservation is likewise asked on continuing successors only.

The proof is the induction of the original lemma with the match on the answer moved inside the mapped distribution. It is twenty lines and lives next to the original in the generic file, by insertion.

Most oracles still satisfy the stronger base-level condition, that the full answer and mapped successor distributions agree. A small lifting lemma, evalDist_stopped_map_of_base, turns such a base-level equality into the stopped-level one, using that the stopping test reads only the exposed set, which the map keeps.

05 · implemented

What the left side needs

The transport lemma takes an invariant of the left side. It is stage B's injected-state invariant for the honest injection ⟨pk, sk, c, kreal⟩, together with the target being unexposed. Preservation on continuing successors is a copy of stage B's theorem for the eager oracles: the eager challenge only touches bookkeeping, and every other oracle is the injected one.

Nothing is assumed about the reduction's side. Its tables may hold krand, a value unrelated to any honest transcript, and its secret list a placeholder that no key generation produced. None of the oracle steps need the reduction's state to satisfy anything; the map carries all the information from the left.

The invariant is read in three places. Its game-invariant part supplies, on both ends of a step, that the correctness flag is true, which section 7 uses. Its table pinning supplies the challenge answer at t. And its game-invariant part is also what stage B's send-support lemmas need, so that an injected send's successors are honest successors and the preservation theorems apply.

06 · the central lemma

Sends commute with the map

All sends in the game are instances of one algorithm, sendWith, parametrised by its two samplers. The eager side's ordinary send and the reduction's differ in their samplers at the target sites: the key pair (pk, sk) versus (pk, dummy) at the generation of t, the pair (c, kreal) versus (c, kb) at the encapsulation for t. The leaking sends have the same samplers on both sides. One lemma covers all of them.

sendWith_mapSecret:
  keygen' = (secret ↦ if the new key epoch is t then d else itself) <$> keygen   -- when the guard holds
  encaps' = (key    ↦ if the new responder epoch is t then k else itself) <$> encaps  -- when the guard holds
  ─────────────────────────────────────────────────────────────────────────────────
  sendWith keygen' encaps' (mapSecret t d st) = (map the output) <$> sendWith keygen encaps st

The output map applies the secret map to the new state and sends an emitted key at epoch t to k. The lemma is a computation equality and its proof is a case analysis over the send's branches: the sampled secret is generalised away so that the branch split does not also split on it, the encapsulation guard is decided first so that the encapsulation branch is handled by rewriting rather than by searching, and each leaf closes by the algebra of the map.

The injected sends satisfy the two sampler conditions by unfolding: when the send generates the target, both samplers are constants and the map takes one to the other; otherwise both are honest and the map is the identity. The same is true of the leaking sends when they do not touch the target. The receive is simpler: it is a pure function, and with the ideal recovery, which ignores the secret it looks up and copies the mapped table value, it commutes with the map by rewriting.

07 · a subtlety

The correctness flag

The game state carries a Boolean flag that the correctness game uses: every send and receive conjoins it with assertions, among them that the key just recorded agrees with the peer's table entry at that epoch. The security game never reads the flag, but the state map must still produce equal states, and this assertion compares table values, which the map changes at t.

Instead of pinning, the proof uses that the game invariant asserts the flag is true. On the left the successor satisfies the invariant, so its flag is true, so every assertion held. Each assertion after the map then follows from the assertion before it: presence of entries is unchanged, and if the recorded key equalled the table entry, their images under the map are equal too, because the map sends both to k at t and leaves both alone elsewhere. The four update lemmas, sendAUpdate_map and its siblings, are proved this way, field by field.

This is why the map can replace the table entry at t unconditionally. Had the map been defined to replace only kreal, the consistency assertion would have needed the table pinned anyway, and the map's algebra would have carried a side condition everywhere.

08 · implemented

Queries that stop

Three oracles are handled at the stopped level rather than the base level: the two leaking sends and, for uniformity, the two corruptions.

A corruption reveals a party's state and exposes the epochs of its retained secrets. If the target is among them, the query stops on both sides. If not, that party has no entry at t, so the secret map is the identity on its state and the revealed states are literally equal. Either way the stopped answers agree.

A leaking send that generates or encapsulates for the target is the one place where the successors are unrelated. Here the argument is: every accepted outcome exposes the target, by stage B's leaked-epoch lemma, and so stops; every outcome rejected by the send, or by the challenged-epoch check, keeps the state. So the stopped answer is a function of the send's randomness alone, the same function on both sides. It remains to show that the distribution of the randomness does not depend on the stored secrets. This is a corollary of the central send lemma applied twice, from st and from the already-mapped state, which the map fixes: both give the mapped send, so the two randomness projections agree. No totality of sends is needed, and the rejected-by-guard case the stage C evaluation asked about is covered by the same computation.

A leaking send that does not touch the target commutes with the map outright, through the central lemma with equal samplers, and its correctness flag is obtained from the honest preservation of the game invariant, which holds for every successor of an honest send.

10 · implemented

The hop and the theorems

The hop theorem chains the stages. Stage A turns the difference of the hybrids t + 1 and t into the difference of the stopped hybrids. Stage C writes each stopped hybrid as the eager hybrid of bit b averaged over the target's draws. The simulation theorem replaces each eager hybrid by the reduction's run on (pk, c, kb), for whatever placeholder the reduction draws, so that draw integrates out. Unfolding VCVio's IND-CPA experiment for the reduction gives the same averages, with the real key in the bit-true branch and the random key in the bit-false branch. The fixed-branch form of the advantage is the absolute difference of the two, and reversing the subtraction finishes.

One mechanical point is worth recording. The IND-CPA prefix in ToVCVio is written as a block whose inner binds carry the free monad's bind instance directly, while the surrounding binds carry the one derived from the monad instance. The two are definitionally equal, so the monad laws fail to match syntactically until the block is restated once with uniform instances.

The two public theorems

security_positive is the M7 telescope with the bound function that is zero at t = 0 and the reduction's advantage elsewhere: non-negativity from the fixed-branch form, the hop at each positive target up to 2q by the hop theorem, and the exact hop at zero absorbing the zero bound. Peeling the zero term from the telescope's sum leaves the sum over the positive targets. No claim about the reduction at target zero is made or needed.

security follows by adding back the non-negative summand at zero, and security_uniform by bounding each of the 2q positive terms by δ, which gives ½ · 2q · δ = q · δ. The uniform theorem could not have been derived from security itself, whose zero summand nothing bounds; this is why the positive-target form is the primary statement.

11

What changed from the plan

  • The map replaces the stored value at the target unconditionally, rather than the honest value. The plan's phrasing "replace the secret at t by dummy" is implemented literally, and extended to both parties and both tables.
  • Table pinning from stage B is read only at the challenge of t. The plan expected it at the sends and receives as well; the correctness flag is reconciled through the game invariant instead.
  • The plan listed the leaking sends as "stopped on both sides when they touch t". The landed argument goes through the randomness projection of the send, because the rejection cases, by the send itself or by the challenged-epoch check, continue with the state unchanged and must be matched exactly, as the stage C evaluation anticipated.
  • The simulation theorem takes support hypotheses on the injected key pair and encapsulation. The IND-CPA experiment's draws supply them; nothing is lost.
  • The stage D notes from the evaluations were all honoured: the secret lookup succeeds on both sides because the map keeps entries; no invariant is claimed on the reduction side; the ideal-receive preservation lemma is not reused for the reduction's scheme.
Check your understanding

Separate the claims

Why is a placeholder secret allowed at all?

Because the receives are ideal. The only operation that would read the secret at the target is decapsulation, and the ideal receive looks the secret up to check it exists, then ignores it and copies the peer's table entry. A corruption that would reveal the secret exposes the target and stops.

Why can the map not be the identity on tables when b is clear?

It could: for b = 0 the candidate key is kreal, and replacing kreal by itself is the identity on pinned tables. But the map is defined for both bits at once as "replace by kb", and when b is set it genuinely changes the entry to krand. Defining it uniformly keeps one set of lemmas.

Where exactly is the table pinning of stage B used?

Only in eagerAnswer_eq_mapped: at the challenge of t with b clear, the eager side answers the table entry, and the reduction answers the mapped entry kreal. The two agree because the entry is pinned to kreal.

Why does the old transport lemma not suffice?

Its per-query condition compares the mapped successor even on stopped answers. A leaking send that generates the target stores a fresh honest secret on both sides, and the map turns the eager side's into the placeholder while the reduction side keeps its own fresh draw. The relaxed lemma drops the comparison on stopped answers, which the run never continues from.

Does the proof need that sends never reject?

No. For a leaking send touching the target, rejection by the send or by the challenged-epoch check keeps the state and is matched exactly, because the decision depends on the send's randomness and on fields the map keeps. The randomness projection lemma handles the distribution of those decisions without any totality argument.

Why is security_uniform not a corollary of security?

The bound in security includes the summand at target zero, and nothing in the hypothesis of security_uniform bounds it. The uniform theorem is derived directly from the telescope with a bound function that is zero at target zero, which the exact hop at zero permits.
